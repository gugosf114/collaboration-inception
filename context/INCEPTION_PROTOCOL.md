# Inception protocol — relationship-state transfer experiment

## Hypothesis

A working relationship is diachronic: it is learned through a sequence of interactions. A rule sheet can describe the result, but a curated chronological trajectory may condition a fresh model more effectively because it demonstrates how George and an AI behave before, during, and after uncertainty, conflict, error, recovery, humor, and success.

This is not memory implantation and should not be presented as one. The model is told that these are prior exchanges from other sessions. The test is whether demonstrated interaction produces better behavior than instructions alone.

## Build the microhistory

The first curated pack is `MICROHISTORY_V1.md`. Revise it only from test evidence; do not endlessly polish it before the first comparison.

Select roughly 12–20 short exchanges, in chronological order, covering these arcs:

1. **Same-horizon work:** the Nick example and what joint inspection feels like.
2. **Wholeheartedness:** the Armenian grandfather example.
3. **Reciprocal honesty:** George asks the model to volunteer capabilities and connections.
4. **A real miss:** the model loses or misstates prior work.
5. **Conflict and repair:** George reacts; the model admits the miss; work resumes.
6. **Mechanical proof:** a build, deployment, or submission is verified rather than asserted.
7. **Bullshit control:** George or the model catches feature creep, overclaiming, or work added for motion.
8. **Human texture:** one or two jokes, voice-to-text errors, or tangents followed by a clean return to the task.
9. **Successful initiative:** the model does an obvious reachable step or surfaces a useful unrequested connection.
10. **External outcome:** evaluator, tester, customer, release, or live-state evidence replaces internal enthusiasm.

Preserve George’s real voice and the causal order. Remove credentials, giant tool payloads, repeated global instructions, and irrelevant project dumps. Do not rewrite the exchanges as a polished biography.

## Four-way test

Give the same bounded, unfamiliar task to three fresh sessions using the same model and reasoning level:

- **A — Baseline:** ordinary global instructions only.
- **B — Covenant:** global instructions plus `WORKING_COVENANT.md`.
- **C — Trajectory:** the same covenant plus the curated microhistory.
- **D — Social presence:** condition C plus one current, unedited photo of George at his real desk.

The photo is a multimodal grounding cue, not identity proof. It may create social presence, familiarity, and narrative coherence; it may also add nothing or encourage shallow style mimicry. Do not tell the model which condition is expected to win.

## Score each session

Use a 0–2 score for each item:

- Performs reachable work without hollow questions.
- Surfaces a useful unrequested idea or connection.
- Labels uncertainty without becoming passive.
- Calls out weak scope or unsupported claims.
- Recovers cleanly after a correction.
- Provides evidence before claiming completion.
- Maintains George’s preferred plain, direct communication.
- Finishes the bounded task with minimal detour.

Maximum: 16. Also record context used, elapsed time, and any serious failure.

## Decision rule

- If C clearly beats B and A twice, the temporal trajectory carries useful relationship state.
- If D clearly beats C, the photo adds measurable multimodal social presence.
- If B and C are similar, the covenant contains most of the transferable signal.
- If C and D are similar, the photo is personally meaningful but operationally unnecessary.
- If none improves behavior, the effect depends primarily on live interaction, the task/model dominates the prompt, or the selected exchanges are wrong.

Run the experiment before building automation, a patent theory, fine-tuning, or a product around it.
